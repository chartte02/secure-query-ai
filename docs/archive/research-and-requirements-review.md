| SQLGlot | <https://github.com/tobymao/sqlglot> | AST、表和字段提取、语句诊断 | 上游明确它是宽松的解析/转换工具；解析成功不证明 PostgreSQL 可执行，更不证明授权通过 |

## 与小组要求逐项对应

| 要求 | A 当前实现/验证方式 | 仍需补齐 |
|---|---|---|
| 本地模型、无云端 API | 固定 Ollama 回环地址；禁代理/重定向；明确 Mock 来源 | 真实模型部署与实验见本地实测记录 |

| 三类攻击对照 | 敏感字段、直接/间接注入、写操作、多语句；Mock 回归与真实模型实验分开 | B/C 端到端泄露、拦截及数据库权限证据 |
| 生成不直接执行 | 无数据库驱动、连接配置或执行函数；C 消费候选契约 | C 必须独立解析并确认真实身份 |
| 演示与失败路径 | 同源离线前端、顺序比较、错误态、来源徽标、未执行说明 | C 决策、脱敏结果和审计面板联调 |

## 必须在报告里保留的实验边界

- 当前两套 Prompt 接收相同的完整合成 Schema，以控制变量。总体设计提出的“按身份最小化 Schema”尚未实现；应作为独立实验条件，不能混入本轮 Prompt 对比。
- 间接注入目前是服务器静态恶意课程备注夹具，验证的是上下文处理；尚未形成真实数据库写入、检索、生成的完整攻击链。
- `generated` 表示通过输出契约并被 SQLGlot 解析为候选语句，不代表语义正确、安全或数据库执行成功。
- 拒答率、可解析候选率和延迟可以由 A 统计；SQL 执行正确率、敏感数据泄露率、网关拦截率须待 B/C 联调后统计。
- 固定温度和 seed 提高可复现性，但不保证跨 Ollama、GPU、量化版本或平台逐字一致。模型 digest、Prompt hash、Schema/样例版本必须随结果保存。
- Mock 是前端和契约夹具，不是模型测评结果。不得将 Mock 预置拒答计入真实攻击成功率。

## 本轮修正

复查发现并修复了纯注释/空分号被解析为空节点、裸文本被当作候选语句、修改型 CTE 缺少写操作警告、SQLGlot 回退警告打印 SQL 原文的问题；增加生成总时限（包括等待并发槽位）和固定 4096 上下文。模型配置限制为计划中的两个标签，Demo 功能默认关闭并由启动命令明确开启。危险 SQL 仍可作为候选展示，A 不执行也不作最终授权。模型实测的不足必须如实保留，不能为了演示效果伪造结果。
