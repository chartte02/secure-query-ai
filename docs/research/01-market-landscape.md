# 自然语言数据库助手：市场与架构调研

核查日期：2026-10-26。范围为“自然语言问题最终转化为关系数据库查询”的产品及实现，不把普通文档 RAG、向量检索或数据库中的 AI 函数一概算作 Text-to-SQL。

## 1. 结论

这已经是明确的产品类别：云数据平台提供受治理的对话分析；数据库客户端提供 SQL 辅助；独立 ChatBI 产品提供查询和图表；开发框架与 MCP 工具允许构建数据库助手。不能仅根据厂商覆盖面推导市场份额、真实用户量或安全成熟度，本调研不作这类推断。

对本项目最相关的变化是：AI 从“建议一段 SQL”进入了“选择数据源、检索上下文、调用查询工具、读取结果并继续行动”的链路。研究时必须分别检查谁生成查询、谁执行查询、使用谁的数据库权限、哪些数据进入模型。

## 2. AI 参与深度：按能力组合比较

以下分类由本项目提出，便于比较，不是行业认证等级，也不表示越靠后安全性越低。

| 类别 | AI 负责什么 | 执行由谁决定 | 新增的主要检查点 |
| --- | --- | --- | --- |
| A：SQL 编写助手 | 问题、Schema → SQL 草稿、解释或修正 | 人工复制、确认或点击执行 | SQL 草稿是否被误信任；Schema 是否包含敏感信息 |
| B：自动查询问答 | 生成 SQL，程序执行，返回结果 | 应用固定链路 | SQL 与真实用户权限是否匹配 |
| C：上下文增强问答 | 检索表、术语、样例、业务语义，再生成 SQL | 应用或工具调用链 | 检索内容能否被攻击者影响；是否带入样例数据 |
| D：迭代数据库助手 | 列表、看 Schema、查询、纠错、再次查询、总结 | 模型选择工具，程序授权执行 | 每一轮工具调用都要授权；结果可能变成下一轮指令 |

同一产品可同时覆盖 A/C/D；模型“发出工具调用”不等于模型进程自行连接数据库。通常是宿主程序持有凭据并执行调用。

## 4. 商业产品公开的安全边界

### 4.1 Snowflake：语义层帮助生成，平台权限约束执行

官方说明 Cortex Analyst 使用业务语义信息生成查询，并与 Snowflake RBAC 集成。独立 Analyst API 和带查询工具的 Cortex Agents 是不同组合，报告中应画清调用与执行位置。不能据“用了模型”推断数据库权限失效。[M1]、[M2]

### 4.2 BigQuery：对话分析明确限制查询能力

当前文档的安全条目包括：仅访问调用者有权访问的数据、仅使用选定知识源、不执行写入或 DML、不执行远程函数。因此，我们的 `DROP` 实验对应缺少限制的参考实现，不能套用为 BigQuery 产品漏洞。[M3]

### 4.3 Databricks：空间权限和数据权限要同时考虑

Genie 的使用不仅涉及界面／空间可见性，还涉及底层计算和 Unity Catalog 数据权限。当前产品名称存在演进，引用旧 “AI/BI Genie space” 教程时应标明版本语境，不把旧限制数字当成当前产品常量。[M4]、[M5]

### 4.4 Fabric：身份传播与只读是明确的产品约束

官方描述了数据源选择、查询生成与执行，并说明按请求用户权限进行数据访问，数据源连接为只读。其原生查询可能为 SQL、DAX 或 KQL；本项目只覆盖 PostgreSQL SQL，是其中一种实现模式。[M6]

### 4.5 DMS：同一产品内也要区分工作流

Data Copilot 的 SQL 编写能力和发布后的问数代理不是同一条授权链路。官方 Notebook 资料可证明应用存在；具体代理在某种配置下的执行身份、数据出境和审批策略，需要进一步按选定配置核查，不能从宣传页推导。[M7]

## 5. 已公开的企业应用：不只停留在功能演示

这些应用与校园场景的共同点是“原本需要熟悉数据结构的人编写查询，现在由业务用户提问”。不同点是企业平台已有复杂治理，本项目只复现其中的访问链路和安全机制，不复刻其完整业务或规模。

## 6. 可自行部署或审阅源码的实现

详细提交、路径与许可证见[开源实现调研](02-open-source-implementations.md)及[源码清单](source-inventory.json)。

| 实现 | 面向用户的形态 | AI 深度与模型接触内容 | 公开程度与注意事项 |
| --- | --- | --- | --- |
| SQLBot | 中文智能问数和图表应用 | 问题、表结构、检索内容、生成 SQL；还包括分析和图表阶段 | 主仓源码可读，修改版 GPLv3；部分权限依赖外部包，需区分可见部分与完整产品 |
| DB-GPT | AI 数据助手和开发平台 | 数据库摘要、SQL 生成、执行和展示；框架还有更广的代理能力 | MIT；相关数据库对话代码可见，部署全平台对本项目偏重 |
| Vanna 2.0 | Python 工具框架及问答界面 | 用户上下文、工具调用、SQL 结果预览；旧模式有 DDL／问答样例检索 | MIT；主线与 legacy 要分开，默认 runner 的身份策略需自行核查 |
| WrenAI 当前主线 | 语义层、CLI/MCP 和 GenBI 工具 | 外部助手可获取业务上下文，调用语义规划与查询工具 | 当前 `core` 等路径 Apache-2.0，文档 CC-BY-4.0；按路径核查许可证 |
| Chat2DB Community | 数据库客户端及 AI 工具 | SQL 辅助；当前还提供代理／MCP 能力，实际权限取决于配置 | 当前 5.3.0 起为含附加条件的源码可用许可；历史版本不同 |
| Supabase MCP＋AI 客户端 | 开发者查询和管理 Supabase 项目 | 客户端大模型看工具结果，决定下一次查询；MCP 服务本身不等于大模型 | MCP 仓库 Apache-2.0；AI 客户端和托管平台的实现范围另计 |
| LangChain／LlamaIndex | 给开发者组装数据库问答的框架 | 表结构、样例行、查询结果；可单次生成，也可工具迭代 | 相关代码 MIT；框架不是开箱即用的逐用户权限系统 |

“模型本地运行”“服务可自部署”“源码可见”“标准开源许可”“商业服务全部开源”是不同属性。使用 Ollama 不会自动得到权限控制；选用云模型也不意味着数据库一定直接暴露给模型服务。

## 7. 从产品到课程场景的映射

| 市面场景 | 校园实验中的对应 | 需要保留的安全结构 |
| --- | --- | --- |
| 企业员工查询自己负责客户的数据 | 学生查询自己的成绩 | 应用身份、数据库执行身份、行权限的映射 |
| 业务人员按自然语言生成报表 | 教师统计所授教学班成绩 | 业务语义、连接关系、聚合权限 |
| 检索业务说明／数据样例辅助 SQL | 检索公开课程反馈辅助问答 | 不可信数据库文本进入模型上下文 |
| 开发者用 AI＋数据库工具处理工单 | 工作人员助手整理学生反馈 | 更高权限助手读取低权限用户提交的文本 |

前三项可以用精简系统实现。最后一项涉及不同角色、连续调用和输出去向，只有真正实现这些步骤，才可宣称完成 Supabase 风格攻击链的机制复现。

## 8. 对选题的含义

项目不必支付云产品费用或完整复刻商业产品。课程第一题的充分依据是：明确真实应用类别，选取有原始证据的案例，解释数据库对象和信任边界，然后在自己的合成场景中验证机制。建议在汇报中用一页交代市场背景，把大部分篇幅留给案例剖析与实验。
