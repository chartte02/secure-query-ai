## 核心建议

研究对象定位为“连接关系数据库的自然语言数据助手”。采用 **P2SQL 论文及作者开源实验作为主要研究依据，LangChain 历史案例和 Supabase MCP 研究演示作为具体案例**；校园教务系统是合成实验载体。Snowflake、BigQuery、Databricks、Fabric、阿里云 DMS 用于证明应用背景和比较安全边界，不据此宣称其有漏洞。

实现采用本地模型＋精简 PostgreSQL 实验环境。优先完成直接越权、上下文中的间接注入、危险 SQL 三条攻击链；Supabase 风格的多轮工具攻击作为扩展。B 的价值主要体现在案例证据、可信身份与权限设计、实验数据和结果判定，不只在建表。

## 调研方法和证据边界

1. 优先使用产品官方文档、项目源码、作者实验仓库和漏洞原始材料；未使用媒体转述证明漏洞。
2. 核查了 **11 个 Git 仓库**，读取 README、许可证及相关源码；所有源码结论固定到提交，而非仅链接可变的 `main`。
3. 源码抽查覆盖候选 SQL 的生成上下文、执行调用、工具权限或查询策略。它是架构分析，不是完整安全审计。
4. 本轮未部署云产品、未运行第三方攻击代码、未下载模型权重、未完成本项目数据库实现；不提供未经实测的成功率、性能或“当前版本可利用”结论。
5. “官方提供该功能”“公开代码显示该调用路径”“研究者在指定环境成功演示”“我们本地实测成功”是四种不同证据，报告必须分别标注。
6. 在 2026-10-26 调研时，工作区仅有要求和两份原始设计文件，没有可审阅的数据库脚本。本文档组中的表结构、脚本名、命令和验收项是当时提出的实施规格；当前已实现内容以数据库接入契约为准。

## 版本核查中需要特别注意的变化

- Vanna 主线已经采用 2.0 架构；旧 RAG 教程对应的代码在 `legacy`。有用户上下文和扩展接口，不代表默认 PostgreSQL runner 自动实现逐用户行权限。
- WrenAI 本次主线包含 CLI/MCP、语义模型和查询策略。不能直接沿用旧版“三服务”架构图描述当前提交。
- SQLBot 许可证含附加条件；部分权限调用依赖 `sqlbot_xpack`，不能把调用点当成完整公开实现。
- Chat2DB 当前许可证明确区分历史版本和 5.3.0 起的源码可用条款，不能沿用网站上的简单 Apache-2.0 宣传概括所有版本。
- Supabase 2025 年文章关于当时托管方式的描述是历史状态；当前文档已经有远程 MCP 配置。历史攻击环境和当前架构要分开写。
