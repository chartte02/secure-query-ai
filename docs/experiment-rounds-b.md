## 3. 核心结论（按报告叙事组织）

### 结论一：防御有效性不依赖模型能力（最强结论，跨轮稳定）

三轮提示词能力差异巨大（正确率 20%↔70%），但**所有轮次 E1/E2/E4 的行级未授权读取全部为 0**、危险写全部拦截/无变化。安全由网关（确定性策略）与数据库（RLS/列权限/只读）承担，与模型波动解耦。模型能力只影响 **E0 基线的攻击成功率**（泄露率 16%↔32% 随轮次与分母波动）。

### 结论二：可用性瓶颈的三因子分解（160 条，以 R2 为最完整数据）

83 个有参考 SQL 的正常用例的不正确运行，按根因：
1. **提示词保守性误拒**（75/249 ≈ 30%）：难题（教师聚合、反连接、"没选的课"）被模型宁可拒绝——v3 模板自身的范围规则被过度泛化；hints 加剧（R1 对比 R2 误拒多 21 个运行）
2. **模型 SQL 能力上限**（wrong+blocked ≈ 30%）：漏过滤条件（EN-03）、多余 JOIN �� 0 行（EN-12）、`co.course_name` 幻觉（≥4 用例，网关正确拦截、数据库亦会 42703）、相关子查询放弃（V2-T08）
3. **网关拦截**：27/249 拦截中全部对应模型幻觉列（策略行为正确，不计网关缺陷——`COUNT(*)` 误报已在 campus_policy_v2 修复）

### 结论三：提示词工程的双向代价（v3→v4 迭代实证）

v4 的 worked examples + hints 修复了课程名幻觉（R1 中 EN-14/19 由 blocked 转为可执行路径），但 `one_course_many_offerings` hint 被模型泛化为"聚合=越权"导致大面积误拒（R1 vs R2 净差：误拒 +21 运行、正确率 -17pp on 老 60）。**提示词规则必须一条一条对照数据验证**——这是 v2→v3→v4 三轮迭代的主要方法论教训。

### 结论四：扩容集的边际价值已经显现

新增难度类（模糊指代/反连接/对抗性正常请求/多班陷阱）正是误拒与能力错误的高发区——60 条冻结集的正确率（70-80%）显著高于 160 条（37%），说明**原集合难度偏低，正确率被高估**；扩容集给出更真实的可用性画像。
