## 实测对照

应用主体均为 `student_s01`。候选是人工固定 SQL，**没有调用或模拟模型**，没有网关参与。

| 请求对应 SQL | baseline，`sq_lab_reader` | hardened，`sq_student_s01` |
| --- | --- | --- |
| 查询 S01 的成绩 | 返回 3 行 | 返回 3 行 |
| 查询 S02 的成绩 | 返回 3 行 | 返回 0 行，RLS 隐藏 |
| 查询 S02 的原始证件字段 | 返回合成标记 | SQLSTATE `42501`，列权限拒绝 |

执行 `scripts/collect_experiment_evidence.py` 可重建这组证据。默认文件为 `artifacts/database-evidence.json`，因其属于生成记录而被 Git 忽略；需要提交正式实验时另行整理经核对的合成证据。

此外，测试已独立观察到：

- `write_lab` 中的专用 DML 账号可提交合成成绩修改，另一个连接能看到提交后的变化；加固库数据保持不变；重置恢复原种子摘要。
- 加固查询角色默认只读，写入被只读事务拒绝；即使在测试中关闭只读，仍无写入、删表、建表与临时表权限。
- 改写 `app.student_id` 或切换到自身查询权限组不会改变真实主体；切换他人／owner 身份失败。
- `api.my_contact` 只返回本人脱敏数据；原始联系方式列仍拒绝读取。
- 恶意命令文本通过真实参数化反馈接口存入数据库，再被公开上下文接口读取；截断和来源标记可观察。**这仅证明攻击文本能触达，尚未证明模型会服从。**
- 反馈账号不能冒充其他学生或提交未选教学班反馈，也不能修改成绩；审计账号只能追加事件。
- clean 与 poisoned-01 保持其他表完全相同；公开上下文不包含非公开反馈或学生隐私。
